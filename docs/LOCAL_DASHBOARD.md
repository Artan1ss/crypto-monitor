# 本地1H实时面板

启动：`python -m btc_monitor.hourly.preview`。
打开：`http://127.0.0.1:8011/dashboard`，默认“实时行情 · 本机直连”。
这个入口不再只是读取旧数据库：后台独立获取公开行情，不启动任何策略或Telegram发送任务。

## 实时模式

- Bybit BTCUSDT合约原生1H价格每30秒刷新，末根是未收盘K线，半透明展示。
- Coinalyze固定六源（Bybit/Binance/Coinbase现货，Bybit/Binance/OKX合约）每120秒刷新最近已收盘小时的CVD、OI、费率。不是全市场，也不是逐笔或秒级指标。
- 首次读取最多169小时，随后只更新最近3小时；前端提供24/72/168小时范围。
- 现货量单位必须通过独立交易所参考成交量核验，不通过时保留缺口，不把缺失当零，不缩小交易所集合冒充完整聚合。
- 本地显示使用30分钟前参考窗口，必要时再用60分钟前窗口，给历史统计充分结算时间；全部原有精确匹配条件不变，默认生产采集仍使用10分钟窗口。尝试过程随元数据保存，合格证据48小时内复用。
- 标出价格接收秒级时间、指标接收时间、最近完整小时、断线和过期状态。价格/指标分别判定新鲜度。
- 当前小时只更新价格，CVD/OI/费率显示到最近已收盘小时；未收盘不等于数据断层。
- 历史回填是当前重新获取的数据，标为 `display_only=true`、`causal=false`、`strategy_eligible=false`，不是当年实时决策证据，不能拿来补发信号。

价格和指标接口：`/hourly/market?hours=72`。此独立入口仅由本机preview接线，继承本机访问保护；没有开放公网。
价格计数 `price_generation`、指标计数 `provider_generation` 只在真实成功取数后增加。读取缓存不会刷新接收时间。
后台任务跟随本地预览进程：关闭程序、电脑睡眠或关机后，本机采集会停止；没有新增开机自启或计划任务。

## 与数据库、云端、信号的关系

实时图表不依赖数据库。信号与数据库健康单独读取，失败时只显示档案不可用，不会挡住已取得的真实行情。
数据库不可用时保留已有图形，但网络失败会标明旧值，绝不使用历史快照冒充实时价格。
本机PostgreSQL可用时将Coinalyze原始小时观察和单位校验元数据追加留存，按原指纹去重、不覆盖；失败后会尝试补存。
不会写入或替换历史 `HourlyBarRecord`、历史信号快照，也不调用信号策略。

“本机信号与数据库归档”仅查询本机数据库，可能没有最新行情或云端信号。
“读取本地快照（非实时）”是此前保存的云端导出文件，不会自动下载今天的Railway数据。
实时模式零条信号只表示本机档案中没有记录，不表示云端没有信号，更不表示已经运行策略但没有机会。

## 配置与故障

- 价格不需要私有交易账户Key。
- 聚合指标使用 `.env` 里已有的 `COINALYZE_API_KEY`，只发送给固定HTTPS官方接口的请求头，不进入回复、Git或日志。
- 无Key或认证失败时价格仍显示；聚合指标明确提示缺少Key/失败，不伪造数据。
- Docker只影响本地原始留存和信号档案，不再是看实时行情的前提。
- 网络失败保留上次行情并标记非实时；恢复后后台自动重试。手动刷新不会绕过提供商限流。
- 数据区间缺失、不完整交易所集合、单位未知、过期，都不能显示为“完整”。OI计数口径未核验，费率为未统一结算周期的非OI加权均值。

API字段和免费Key用法参考：[Coinalyze官方说明](https://api.coinalyze.net/v1/doc/)。当前实现保留已有每分钟25个symbol cost的本机限流预算与退避，不新增付费订阅。
